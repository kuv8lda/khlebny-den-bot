# Решения и ограничения

## SQLite и состояние диалога

Бот использует stdlib `sqlite3` через `asyncio.to_thread` для FSM и заказов. Пакет называется `khlebny_bot`; точка входа: `python -m khlebny_bot.main`.

Корзина и заказы могут храниться в разных файлах (`FSM_DB_PATH` и `ORDERS_DB_PATH`), поэтому создание заказа и очистка корзины не образуют общую транзакцию. Уникальный `checkout_token` позволяет повторить создание без второго заказа.

Бот создаёт заказ из снимка позиций на экране подтверждения. Просмотр страниц не меняет снимок. После создания бот очищает корзину и оформление, в том числе при сбое отправки в панель. Для повтора он читает заказ и ключ из базы заказов.

`/cancel` сбрасывает незавершённое оформление, но оставляет корзину. Пользователь очищает её отдельной кнопкой. Количество меняется кнопками в диапазоне 1–20; ввода числа нет. Даты бот показывает в UTC.

## Каталог

Без `PANEL_API_KEY` бот использует демонстрационный каталог из `catalog.py`. С ключом он загружает каталог панели до начала polling и останавливает запуск при ошибке: устаревший ID может указывать на другой товар.

При изменении каталога бот сбрасывает незавершённые корзины и оформление, сохраняя заказы. После изменения ассортимента или цен панели нужен перезапуск бота. ID товаров в API должны быть целыми числами без дублей; строки вида `"1"` клиент не принимает.

## Доставка заказа в панель

До HTTP-запроса бот сохраняет заказ с `pending_panel_sync=True`. Для `Idempotency-Key` он использует сохранённый токен оформления. Успех снимает флаг; ошибка оставляет заказ для ручного повтора. Фоновой очереди отправки нет.

Клиент повторяет сетевые ошибки и HTTP 5xx до трёх попыток с задержками 0,25 и 0,5 секунды. На всех попытках он использует один ключ. При создании заказа ответы 200/409 означают дубль; другие HTTP 4xx приводят к `PanelError` без повтора.

## Владелец и статусы

Доступ ограничен Telegram ID из `OWNER_TELEGRAM_IDS`. Неверное значение останавливает запуск. Команды владельца скрыты из публичного меню Telegram.

Номер в карточке совпадает с номером заказа клиента. ID панели бот хранит в `orders.panel_order_id`. Локальный статус `new` соответствует `pending` панели. Без ID панели бот не предлагает сменить статус.

Панель проверяет допустимость перехода. При HTTP 409 бот сообщает о конфликте и использует текущий статус из ответа, если панель его передала. `/owner` считает заказы по локальной базе; события панели обновляют эти данные.

Бот уведомляет владельцев после ответа клиенту. Сбой уведомления не отменяет сохранённый заказ. Телефона в карточке нет: бот его не собирает.

## События и доставка уведомлений

Один воркер на базу заказов обрабатывает события панели по возрастанию ID, пакетами до 50. Получателя он определяет по локальному `panel_order_id`; событие не содержит Telegram ID.

После отправки воркер фиксирует курсор и локальный статус одной транзакцией. Если процесс завершится между доставкой в Telegram и записью в SQLite, клиент может получить повтор. Общей транзакции Telegram и SQLite нет.

При временной ошибке воркер оставляет курсор перед неотправленным событием и повторяет обработку в следующем цикле. Заблокировавших бота клиентов, неизвестные заказы и статусы он пропускает с записью в лог. Восстановление связей старых или потерянных заказов не предусмотрено.

## Удаление и срок хранения данных

`/forget` удаляет локальные заказы и их состав одной транзакцией, затем все FSM-записи пользователя, включая другие чаты и темы. После этого бот запрашивает анонимизацию в панели. При ошибке пользователь повторяет команду; очереди повторов нет.

Панель очищает имя, телефон и username, но сохраняет Telegram ID, комментарии и историю заказов. Команда не удаляет сообщения Telegram и резервные копии. Начатая отправка события может завершиться во время удаления: воркер событий и `/forget` не используют общую блокировку.

При запуске и каждый час бот удаляет FSM-записи старше семи дней без изменений. Чтение не продлевает срок. Миграция даёт старым записям новый срок, поскольку их возраст неизвестен. Автоматического удаления заказов нет.

Антиспам-счётчики содержат ID и время создания заказа без имени и состава. `/forget` не удаляет их, чтобы пользователь не обходил квоту. Бот очищает устаревшие счётчики при создании заказов и в фоновой очистке; при работающем боте срок не превышает двух часов.

## Ограничения и завершение работы

Checkout допускает пять новых заказов за скользящий час. Бот проверяет квоту и записывает счётчик одной SQLite-транзакцией. Повтор существующего заказа не тратит квоту. Низкоуровневый `OrdersRepo.create` без `enforce_rate_limit` остаётся доступен для импорта и тестовых фикстур.

Middleware учитывает активные обработчики до FSM-lock, включая тех, кто ждёт блокировку. `SimpleEventIsolation` сериализует действия одного пользователя в чате. При SIGTERM/SIGINT бот ждёт обработчики, останавливает фоновые задачи, затем закрывает HTTP-сессии и SQLite.

Docker даёт процессу 60 секунд на остановку. Само приложение не ограничивает ожидание обработчиков; после этого срока Docker может отправить SIGKILL.

## Развёртывание и проверки

Образ использует Python 3.13 slim и UID/GID `10001:10001`. Сборка нормализует права чтения исходников, чтобы файлы с локальным режимом `0600` не ломали импорт. Allowlist в `.dockerignore` исключает секреты и базы из контекста сборки.

Compose запускает бот и готовый образ панели. Пользователь задаёт `PANEL_IMAGE`, `PANEL_DATA_DIR` и отдельный `.env.panel` по документации панели. `depends_on` не гарантирует готовность её API. Инструкция запуска, резервирования и отката: [docs/DEPLOY.md](docs/DEPLOY.md).

CI проверяет Python 3.11/3.12/3.13, Ruff, pytest и Docker smoke-тест. Зависимости заданы диапазонами без lock-файла. Проверки с HTTP- и Telegram-моками не подтверждают работу живой интеграции.

В прежней проверке заказ из Telegram дошёл до панели с `source='telegram'`, верными составом и суммой. Живая приёмка уведомлений владельцу и клиенту в прежних записях не подтверждена. Для текущей версии используйте [чек-лист](docs/DEPLOY.md).
