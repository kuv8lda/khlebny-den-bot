# Отклонения от ТЗ

- Пакет называется `khlebny_bot` (не `bot`): запуск через `python -m khlebny_bot.main`, а не корневой main.py.
- Конфиг на этапе 0 содержит только BOT_TOKEN и LOG_LEVEL; параметры панели добавим вместе с интеграцией.
- SQLite-хранилище FSM не входит в этап 0, добавилось вместе с первым сценарием на FSM.

# Отклонения и допущения

- Цены в `khlebny_bot/catalog.py` — временные значения.
- `/cancel` сбрасывает состояние FSM и данные оформления, но не корзину; очистка корзины — отдельная кнопка.
- Количество меняется кнопками «−»/«+» в диапазоне 1–20, а не вводом числа.
- FSM-хранилище SQLite написано на stdlib `sqlite3` через `asyncio.to_thread`, без aiosqlite; репозиторий заказов — так же.
- `httpx` и `respx` не подключены: сети нет, добавим на этапе 3.

# Этап 2

- В `orders` добавлена колонка `checkout_token` (UNIQUE): повторное «Подтвердить» возвращает уже созданный заказ, а не создаёт второй.
- «Заказ + очистка корзины одной операцией» заменено на идемпотентное создание с последующей очисткой: корзина лежит в FSM, а заказы могут быть в другом файле (`ORDERS_DB_PATH`), общей транзакции нет.
- Заказ строится из снимка позиций с экрана подтверждения (хранится в FSM); после оформления корзина очищается целиком.
- Оформление и «Мои заказы» вынесены в `khlebny_bot/checkout.py` с отдельным роутером; в main он подключается после `handlers`, чтобы команды и кнопки меню работали в любом состоянии.
- Дата заказа показывается в UTC с пометкой.

# Этап 4 (отправка заказов в панель)

- `pending_panel_sync` — флаг отложенной синхронизации: `True` если заказ не удалось отправить в панель при создании.
- Дубли по `Idempotency-Key` (200/409) не повторно вызывают панель — обрабатываются как успех с `duplicate=True`.
- `PanelError` при отправке → заказ уже сохранён локально, флаг `pending_panel_sync=True`, пользователь получает нормальный ответ.
- `PanelClient.create_order(payload)` в `panel.py`; 201 — успех, 200/409 — дубль, 422/другое — `PanelError`.
- `panel_client: PanelClient | None` инжектируется в `on_confirm` через aiogram DI; `None` если `PANEL_API_KEY` пуст.
- Новых зависимостей нет. Панель не тронута.

- Настройки панели добавлены в существующий `config.py` (pydantic-settings), отдельного модуля для чтения `.env` нет.
- `httpx` и `respx` уже были в `pyproject.toml`; новых зависимостей нет (строка выше про «не подключены» устарела).
- `BOT_API_TOKEN` в проекте не использовался: `BOT_TOKEN` — токен Telegram, `PANEL_API_KEY` — ключ панели.
- Пустой `PANEL_API_KEY` выключает интеграцию; при сбое панели бот берёт устаревший кэш или хардкод-каталог, повтор запроса — не раньше чем через `CATALOG_TTL_SECONDS`.
- `id` из панели принимается только как целое (строка `"1"` — ошибка формата); дубли `id` — ошибка.
- `panel.py` пока не подключён к `handlers`/`checkout`/`main`: они читают `catalog.CATALOG`.
