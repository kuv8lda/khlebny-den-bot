# Демонстрация бота + панели
https://github.com/user-attachments/assets/37505b09-64de-4109-abb0-cb2a4fc5f432

Telegram-бот вымышленной пекарни «Хлебный день» на aiogram 3 и long polling. Заказы демонстрационные: пекарня их не исполняет, платежей нет.

Покупатель выбирает выпечку, меняет корзину и подтверждает заказ. Бот хранит заказы и состояние диалога в SQLite. При подключении orders-admin-panel он отправляет заказы в панель, сообщает клиентам о статусах и даёт владельцам менять статус из Telegram.

## Запуск

Нужны Python 3.11+ и токен от @BotFather.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
```

Впишите `BOT_TOKEN` в `.env` и запустите:

```bash
python -m khlebny_bot.main
```

Для Docker и Compose следуйте [инструкции развёртывания](docs/DEPLOY.md). Compose требует готовый образ панели из отдельного проекта.

## Настройки

Задайте переменные в окружении или `.env` (файл в `.gitignore`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | Обязательна | Токен Telegram-бота |
| `FSM_DB_PATH` | `data/fsm.sqlite3` | Состояние диалогов и корзины |
| `ORDERS_DB_PATH` | Значение `FSM_DB_PATH` | Заказы, курсор событий и состояние уведомлений о ценах |
| `PANEL_BASE_URL` | `http://127.0.0.1:5000` | Адрес панели, доступный боту |
| `PANEL_API_KEY` | Пусто | Bearer-токен; пустое значение отключает интеграцию |
| `PANEL_TIMEOUT_SECONDS` | `5` | Таймаут одной попытки запроса к панели |
| `EVENTS_POLL_INTERVAL` | `5` | Интервал опроса событий и цен, секунды; положительное конечное число |
| `CATALOG_PUSH_TOKEN` | пусто | Общий секрет push-уведомлений панели; не менее 32 байт |
| `CATALOG_PUSH_HOST` / `CATALOG_PUSH_PORT` | `127.0.0.1` / `8081` | Адрес HTTP-приёмника каталога |
| `CATALOG_TTL_SECONDS` | `60` | TTL для автономного `CatalogProvider`, секунды; на push-обновления не влияет |
| `OWNER_TELEGRAM_IDS` | Пусто | ID владельцев через запятую, например `123,456`; неверное значение останавливает запуск |

Бот пишет логи уровня `INFO`; при запуске он не использует настройку `LOG_LEVEL`.

## Команды

| Команда | Действие |
|---|---|
| `/start` | Показать кнопки меню, корзины и истории заказов |
| `/menu` | Показать товары по пять на странице; нажатие добавляет одну штуку |
| `/cart` | Изменить количество (1–20 на товар), удалить позиции или начать оформление |
| `/orders` | Показать последние пять заказов и их состав |
| `/cancel` | Отменить незавершённое оформление, сохранив корзину |
| `/help` | Показать справку |
| `/privacy` | Прочитать условия хранения данных |
| `/forget` | Удалить локальные данные и запросить анонимизацию в панели |
| `/owner` | Показать сводку владельцу |
| `/competitor` | Запросить цены конкурентов из панели |

Оформление: имя (1–40 символов), необязательный комментарий (до 200), подтверждение. Бот сохраняет снимок товаров и цен с экрана подтверждения. Телефон он не запрашивает.

Команды владельца доступны ID из `OWNER_TELEGRAM_IDS` и скрыты из публичного меню команд. Владелец должен написать боту, прежде чем тот сможет присылать уведомления.

## Каталог

Локальное меню содержит 20 демо-товаров, общих с панелью. ID 7 снят с продажи.

При включённой интеграции бот однократно загружает каталог при старте. При изменении каталога панель отправляет новую версию на HTTP-приёмник бота; периодического опроса каталога нет. Для push задайте общий секрет `CATALOG_PUSH_TOKEN` и настройте адрес бота в панели. При недоступности панели бот сохраняет последние полученные цены, в том числе после перезапуска; если сохранённого каталога ещё нет, используется встроенный. При изменении каталога бот сбрасывает незавершённые корзины и оформление, но сохраняет снимки созданных заказов. Откройте `/menu`, чтобы заменить старые кнопки.

## Интеграция с панелью

Бот использует Bearer-авторизацию для `/api/integrations/*`:

- `GET /catalog`: массив товаров с `id`, `name`, `price_cents`.
- `POST /orders`: создание заказа с сохранённым токеном оформления в `Idempotency-Key`.
- `GET /events?since_id=N&limit=50`: события статусов по возрастанию ID.
- `PATCH /orders/<id>/status`: действие владельца с телом `{"status": "..."}`.

### Отправка заказа и повтор

Бот сохраняет заказ до запроса панели. При сетевой ошибке или HTTP 5xx он делает до трёх попыток с задержками 0,25 и 0,5 секунды. Таймаут каждой попытки задаёт `PANEL_TIMEOUT_SECONDS`. Ответы 200/409 при создании заказа клиент считает дублем; остальные HTTP 4xx он не повторяет.

При сбое отправки заказ остаётся с `pending_panel_sync=1`. Бот очищает корзину и оформление, затем предлагает «Повторить отправку» в сообщении результата и карточке заказа. Повтор отправляет сохранённый заказ с прежним ключом. Фоновой очереди отправки нет.

### Уведомления о статусах

Один воркер на базу заказов опрашивает события панели и отправляет клиентам статусы. После доставки он сохраняет курсор и локальный статус одной транзакцией. Авария между отправкой в Telegram и записью в SQLite может привести к дублю уведомления.

При ошибке панели или Telegram воркер повторяет обработку в следующем цикле, не продвигая курсор за неотправленное событие. Заблокировавших бота получателей, неизвестные заказы и статусы он пропускает с записью в лог. Локальные изменения видны в `/orders` и `/owner`.

Владельцы получают карточки новых заказов с кнопками доступных переходов:

```text
pending → paid или cancelled
paid → shipped или cancelled
shipped → completed
```

Локальный `new` соответствует `pending`. Без ID панели кнопок смены статуса нет. При HTTP 409 бот сообщает о конфликте и обновляет карточку, если панель передала текущий статус. Ошибка уведомления владельца не отменяет заказ клиента.

### Цены конкурентов

Панель должна поддерживать `GET /api/integrations/competitor-prices`. Если этого API нет, добавьте его в панель. Панель или её парсер сопоставляет товары конкурента с товарами пекарни. [Контракт и пример JSON](README.md#competitor-prices).

Отдельный воркер сравнивает соседние обработанные цены для каждого владельца и уведомляет об изменении **больше 5%**. Первый снимок задаёт исходную цену. Изменение на 5% и меньше обновляет её без уведомления. При исходной цене 0 бот сохраняет новую цену без расчёта процента.

SQLite хранит исходные цены для каждого владельца. При временной ошибке Telegram воркер повторит доставку этому владельцу в следующем цикле; заблокировавших бота получателей он пропускает. Сбой после отправки до сохранения может дать дубль. Опрос не видит промежуточных изменений цен между снимками. Нужен один воркер на базу; ежедневных дайджестов нет.

`/competitor` читает текущий снимок панели, не меняя состояние уведомлений, и сообщает об отсутствии данных или ошибке панели.

## Приватность

`/forget` удаляет локальные заказы, состав, корзины и FSM пользователя во всех чатах, затем запрашивает анонимизацию в панели. При ошибке панели повторите команду позже; очереди повторов нет.

Панель очищает имя, телефон и username, но сохраняет Telegram ID, комментарии, заказы, суммы и события. Команда не удаляет сообщения Telegram и резервные копии.

При запуске и каждый час бот удаляет корзины и незавершённое оформление старше семи дней без изменений. Старые записи при миграции получают новый срок хранения. История заказов остаётся до `/forget`.

Антиспам-счётчики содержат Telegram ID и время создания заказа. Они сохраняются после `/forget` для защиты квоты; бот удаляет их в течение двух часов работы.

## Ограничения и остановка

- Оформление допускает пять новых заказов за скользящий час. Повтор существующего заказа не расходует квоту. SQLite сохраняет счётчики при перезапуске.
- Входящие сообщения и кнопки делят лимит: одно событие за 0,5 секунды на пользователя. Лишние сообщения бот игнорирует, на лишние нажатия отвечает пояснением.
- Изоляция FSM выполняет действия одного пользователя в одном чате по очереди.
- При SIGTERM/SIGINT бот останавливает polling, ждёт обработчики и воркеры, затем закрывает сессии и базы.

## Разработка

```bash
ruff check .
pytest -q
```

Тесты используют моки и не требуют сети. CI запускает Ruff и pytest на Python 3.11, 3.12 и 3.13, собирает Docker-образ и проверяет запись в том от непривилегированного пользователя. Зависимости заданы диапазонами в `pyproject.toml`, lock-файла зависимостей нет.

См. [решения](DECISIONS.md), [правила Telegram UX](docs/TELEGRAM_UX.md) и [живую приёмку](docs/DEPLOY.md). Тесты с моками не измеряют задержку Telegram и не проверяют работающую панель.
