# Развёртывание

## Требования и границы

- Linux-сервер, Docker Engine и Compose v2, исходящий HTTPS к Telegram и доступ к панели.
- Один экземпляр бота на токен и SQLite-базу. Входящий порт боту не нужен: long polling.
- Демо без реальных платежей. Перед эксплуатацией пройдите живую приёмку ниже.
- Панель — отдельный проект. Этот репозиторий не собирает и не меняет её код.
  Compose использует **готовый образ** orders-admin-panel. Его Dockerfile, команду
  запуска, переменные и миграции нужно проверить по документации самой панели.

## Вариант 1: бот без панели или с уже работающей панелью

```bash
cp .env.example .env
# Впишите BOT_TOKEN. Без панели оставьте PANEL_API_KEY пустым.
chmod 600 .env
docker build -t khlebny-den-bot:local .
docker volume create khlebny-bot-data
docker run -d --name khlebny-bot --init --restart unless-stopped \
  --stop-timeout 60 --env-file .env \
  -e FSM_DB_PATH=/app/data/fsm.sqlite3 -e ORDERS_DB_PATH=/app/data/orders.sqlite3 \
  -v khlebny-bot-data:/app/data khlebny-den-bot:local
```

Для внешней панели задайте доступный **из контейнера** `PANEL_BASE_URL` и ключ.
`127.0.0.1` внутри контейнера — сам бот, не хост и не другой контейнер.
Для удалённой панели используйте HTTPS. Не запускайте одновременно локальный
`python -m khlebny_bot.main` с тем же токеном.

Образ использует Python 3.13 slim и UID/GID `10001:10001`. Том `/app/data`
доступен этому пользователю. Для bind mount заранее создайте каталог с такими
правами; не исправляйте проблему запуском бота от root. `.env`, базы и тестовые
артефакты исключены из build context через allowlist в `.dockerignore`.

## Вариант 2: Compose — бот + панель

1. Подготовьте образ панели вне этого репозитория. Он должен сам запускать
   HTTP-сервер на `0.0.0.0`, а не `127.0.0.1`, и поддерживать API `/api/integrations/*`.
2. Скопируйте `.env.example` в `.env`, задайте `BOT_TOKEN`, `PANEL_API_KEY` и
   `OWNER_TELEGRAM_IDS` при необходимости.
3. В `.env` заполните параметры Compose:

   ```dotenv
   PANEL_IMAGE=orders-admin-panel:local
   # Укажите РЕАЛЬНЫЙ абсолютный каталог данных из документации образа панели:
   PANEL_DATA_DIR=/replace/with/panel/data/directory
   PANEL_PORT=5000
   PANEL_HOST_PORT=5000
   ```

   `PANEL_PORT` — внутренний порт HTTP-сервера панели. `PANEL_HOST_PORT` — порт
   на хосте, по умолчанию 5000. `PANEL_IMAGE` и `PANEL_DATA_DIR` обязательны;
   заглушку пути нельзя оставлять. Для релиза предпочтителен образ по digest.
4. Создайте `.env.panel` с настройками **самой панели**, включая её ключ интеграции,
   совпадающий с `PANEL_API_KEY` бота, секрет сессий и путь к базе внутри
   `PANEL_DATA_DIR`. Имена переменных берите из документации панели: файл настроек
   бота не является конфигурацией панели. Если образ требует миграций/инициализации
   или дополнительных томов, выполните это по его инструкции перед запуском.
5. Защитите файлы и проверьте конфигурацию без вывода секретов:

   ```bash
   chmod 600 .env .env.panel
   docker compose config --quiet
   docker compose up -d --build
   docker compose ps
   docker compose logs --tail=100 bot
   ```

Compose фиксирует пути бота в `/app/data/`, URL панели — `http://panel:PANEL_PORT`.
Тома `bot-data` и `panel-data` независимы и сохраняются при пересоздании контейнеров.
`depends_on` задаёт порядок запуска, но **не** готовность API. Бот повторяет
неудачные опросы; запросы клиентов при недоступности панели сохраняют корзину.
Универсальный healthcheck панели не задан, поскольку его endpoint неизвестен.

Панель опубликована только на `127.0.0.1`. Для доступа извне настройте защищённый
reverse proxy с TLS и аутентификацией либо SSH-туннель. Не публикуйте API-ключи
и вывод `docker compose config` без `--quiet`.

## Проверка после запуска

1. Клиент и каждый владелец пишут боту `/start`.
2. `/menu` → корзина → имя → комментарий → подтверждение: заказ появился в панели,
   владельцу пришла карточка. Сверьте позиции, сумму и Telegram ID.
3. Кнопкой владельца измените статус: панель обновилась, клиент получил уведомление
   после опроса. Проверьте отказ для чужого ID и конфликт устаревшего статуса.
4. На тестовом окружении остановите панель: подтверждение сообщает о сбое,
   корзина сохранена. Запустите панель и повторите подтверждение: заказ не дублируется.
5. Проверьте `/privacy`, `/forget`, восстановление FSM после перезапуска,
   лимит пяти заказов и остановку по SIGTERM.
6. Проверьте `docker compose restart bot` и продолжение курсора событий без
   повторов уже зафиксированных событий. Аварийная доставка не имеет exactly-once.

## Остановка, обновление и откат

```bash
docker compose stop bot  # SIGTERM, до 60 с на обработчики и фоновые задачи
# Сделайте резервную копию по следующему разделу.
docker compose up -d --build bot
```

Сохраните предыдущий образ (`docker image tag <image-id> khlebny-den-bot:previous`)
и git revision перед обновлением. Для воспроизводимого релиза фиксируйте digest
базового/панельного образа и версии Python-зависимостей: текущие диапазоны
в `pyproject.toml` не являются lock-файлом. Панель обновляйте отдельно по её инструкции.

Для отката вернитесь к предыдущей ревизии и пересоберите бота либо используйте
сохранённый образ через Compose override `services.bot.image` с `--no-build`.
При несовместимой схеме восстанавливайте соответствующую резервную копию на
остановленном боте. Откат курсора/базы может повторно доставить события.

Лимит остановки — 60 с; если обработчики не успевают (например, Telegram завис),
Docker завершит процесс принудительно. Приложение не гарантирует ограниченное
время drain. Подбирайте `stop_grace_period` по реальным таймаутам.
Не используйте `docker compose down -v`: это удаляет постоянные данные.

## Резервное копирование SQLite бота

Остановите бота, чтобы база и её WAL были согласованы. Пример для Compose:

```bash
mkdir -p backups
docker compose stop bot
docker compose run --rm --no-deps -T --entrypoint tar bot \
  -C /app/data -czf - . > backups/bot-data.tar.gz
# Проверьте успешное завершение tar и сохраните архив в защищённом хранилище.
docker compose start bot
```

Архив содержит персональные данные; ограничьте доступ, шифруйте внешние копии
и задайте срок хранения. Панель и её том копируйте отдельно по её инструкции.

Восстановление **заменяет** данные: остановите бота, сначала сохраните текущую
копию. Восстанавливайте в пустой том, чтобы не оставить старые WAL/SHM-файлы.
Укажите этот том как `bot-data` через Compose override и загрузите доверенный архив:

```bash
# Пример загрузки в новый том, перед подключением к сервису:
docker volume create khlebny-bot-restored
docker run --rm -i --user 10001:10001 --entrypoint tar \
  -v khlebny-bot-restored:/app/data khlebny-den-bot:local \
  -C /app/data -xzf - < backups/bot-data.tar.gz
```

После подключения восстановленного тома запускайте только один экземпляр бота.
Удаление через `/forget` не удаляет старые архивы и сообщения Telegram.
